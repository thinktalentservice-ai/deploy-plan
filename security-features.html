0 What this means for the client

The one-paragraph version your security reviewer needs.

Every variant can be made secure enough for a standard SaaS client. They differ in who does the work and how much is free. The Cloudflare front door gives the strongest edge security (WAF + unmetered DDoS + bot management + TLS + AI scraper blocking) at near-zero cost and concentrates all routing controls in one place. AWS and GCP add the deepest network isolation, data-encryption control (BYOK/CMEK) and regulated-industry compliance (HIPAA / PCI / FedRAMP with a signed BAA) — at the cost of a larger surface you must configure correctly. Variant ④ (GCP + Cloudflare) is the recommended balance: Cloudflare's free edge security in front of Cloud Run's network isolation + compliance behind it. In 2025–2026, supply-chain attacks doubled — SBOM generation, SLSA provenance and Sigstore signing are now baseline expectations, not optional extras.

2 Security features in each variant

What's built in (✓), what's optional/configurable (~), what's missing or weak (✕), and what you must lock down (🔒).

① AWS

ECS Fargate/EC2 + ALB + CloudFront + WAF + VPC
  • Edge: CloudFront + AWS WAF managed rule groups + AWS Shield Standard (always-on L3/4 DDoS); WAF now includes enhanced CloudFront Rule Packs with automated TLS provisioning
  • Network: full VPC — private subnets, security groups, NACLs, PrivateLink, VPC peering; Shield Network Security Director auto-discovers & prioritises network risks across accounts
  • Identity: IAM — extremely fine-grained, roles, SCPs, permission boundaries; Cognito for app auth; Verified Access for Zero Trust
  • Secrets: Secrets Manager with automatic rotation; SSM Parameter Store
  • Data: KMS with BYOK / customer-managed keys, encryption at rest everywhere, TLS via ACM
  • Compliance: SOC 2, ISO 27001, HIPAA, PCI-DSS, FedRAMP — signs a BAA
  • Audit/supply-chain: CloudTrail (every API call), GuardDuty, Inspector, ECR image scanning; SBOM export via Inspector; SLSA provenance via AWS CodeBuild
  • Cost: WAF managed rules pricing updated (June 2026): $5/ACL/mo + $1/rule/mo + $0.60/M requests; Shield Advanced $3,000/mo fixed fee (confirmed); GuardDuty, Secrets Manager billed separately; L7 DDoS protection free up to 50B WAF requests/mo for Shield Advanced customers
  • Surface: largest — public S3, open SGs, over-broad IAM are the classic self-inflicted breaches
  • Must do: least-privilege IAM, private subnets for backends, WAF rate rules, patch base images, enable Shield Network Security Posture Management

② Vercel + Railway + Cloudflare

CF Worker front door → Vercel (FE) + Railway (BE)
  • Edge: Cloudflare WAF + unmetered DDoS (included on every plan) + Bot Management / Turnstile + rate limiting + AI Scraper & Crawler blocking (one-click, free) — best-in-class
  • AI threat protection: Block GPTBot, ClaudeBot, PerplexityBot and 1 M+ customers' worth of known LLM crawlers with a single dashboard toggle; automatically updated fingerprints
  • Zero Trust: Cloudflare Access + MCP Server Portals (Open Beta) — consolidate all MCP tool calls and set user-level policies per gateway and per MCP server; WARP connector now extends Zero Trust to private networks (on-prem / internal services)
  • Identity at edge: Worker validates JWT / Cloudflare Access (Zero Trust) before the request reaches any origin; AI Prompt Protection to block sensitive data leakage to LLMs
  • TLS: automatic, zero-config, everywhere
  • Secure by default: fewest knobs → fewest self-inflicted holes; provider patches the platform
  • Network: mostly public + token/secret auth — limited deep isolation (no full VPC)
  • Secrets: per-platform env vars, manual rotation (redeploy); no BYOK on Railway
  • R2 storage: improved CORS policies — granular per-bucket CORS rules now configurable without a Worker proxy; reduces surface for misconfigured cross-origin access
  • Compliance: Cloudflare & Vercel SOC 2 strong; Railway lighter — fine for standard SaaS, weaker for HIPAA/PCI
  • Cost: most edge security is free / included — biggest budget win; Turnstile free with unlimited challenges
  • Must do: origin-lock secret header so users can't bypass CF and hit Vercel/Railway URLs directly; env-var hygiene; enable AI scraper block + WAF managed ruleset

③ GCP

Cloud Run + Global LB + Cloud Armor + Cloud CDN
  • Edge: Cloud Armor WAF — managed OWASP rules + Google-edge DDoS absorption + rate-limit rules; enhanced WAF body inspection expanded to 64 KB (up from 8 KB); Thales Imperva-powered managed rules for zero-day coverage (preview); Adaptive Protection now GA — ML-based DDoS detection and auto-generated mitigation rules across L3/L4 and L7
  • Hierarchical policies: Cloud Armor Hierarchical Security Policies (GA) — centrally manage rules across all 300 apps from one org-level policy; org-scoped address groups for IP allowlists/denylists
  • Network: VPC, Cloud Run ingress = internal + LB only, VPC connectors, internal load balancing; Cloud NGFW enforces service-centric security for Cloud Run & GKE traffic
  • Identity: fine-grained IAM; Cloud Run service identity + ID tokens; IAP (Identity-Aware Proxy) for zero-trust; Workload Identity Federation
  • Secrets: Secret Manager (versioned, IAM-scoped); rotation via scripts/automation
  • Data: default encryption + CMEK / BYOK, Google-managed TLS certs (auto)
  • Compliance: SOC 2, ISO 27001, HIPAA, PCI-DSS, FedRAMP — signs a BAA
  • Audit/supply-chain: Cloud Audit Logs, Security Command Center, Artifact Analysis + Binary Authorization; SBOM export GA; SLSA provenance from Cloud Build; Model Armor for LLM prompt/response filtering
  • Surface: medium — strong defaults, you still own IAM & Armor policy tuning
  • Must do: set Cloud Run ingress to internal+LB, scope IAM, enable Armor hierarchical policies + managed rules, audit logs, Binary Authorization

★ ④ GCP + Cloudflare (recommended)

CF Worker edge → Cloud Run origins (ingress-locked)
  • Edge (CF): free best-in-class WAF + unmetered DDoS + bot + rate limiting + edge JWT/Access + AI scraper blocking for all 300 apps
  • Origin (GCP): Cloud Run network isolation + Armor hierarchical policies, VPC, IAM, CMEK/BYOK, compliance + BAA on the backend
  • Identity: edge pre-auth at the Worker and Cloud Run IAM/ID-token on the origin — defence in depth; MCP Server Portals for AI agent Zero Trust
  • AI security: CF AI Prompt Protection + GCP Model Armor — two independent layers filtering LLM interactions at edge and at origin
  • Audit: Cloudflare logs at the edge + Cloud Audit Logs / SCC at the origin; SBOM + SLSA provenance from Cloud Build
  • Cost: edge security free; only GCP-side tools (Secret Manager, SCC, Artifact Analysis) are paid
  • Surface: two vendors, but only the Worker to "operate"; cross-cloud hop adds minor latency
  • Mandatory: lock the origin — Cloud Run ingress internal-and-cloud-load-balancing or a Worker-injected X-Origin-Secret header, so attackers can't hit *.run.app directly and skip the edge

5 HTTP security headers — 2026 recommendations

Headers cost nothing to add; over 95% of sites still score below a "B" on Mozilla Observatory. Set these centrally at the edge (CF Transform Rules or CloudFront response-headers policy) so all 300 apps inherit them.

HeaderRecommended valueStatus 2026Notes
Strict-Transport-Securitymax-age=63072000; includeSubDomains; preloadRequiredTwo-year max-age. Add preload only after confirming all subdomains are HTTPS. Prevents SSL-stripping attacks.
Content-Security-PolicyAllowlist-based; use nonces/hashes instead of unsafe-inlineRequiredDeploy in Report-Only mode first. Never use unsafe-inline + unsafe-eval — they negate XSS protection entirely. Most powerful header available.
X-Frame-OptionsDENY or SAMEORIGINRequired (or CSP frame-ancestors)Use CSP: frame-ancestors 'none' as the modern equivalent; X-Frame-Options is legacy fallback for older browsers.
X-Content-Type-OptionsnosniffRequiredBlocks MIME-type sniffing attacks. Zero downside; add universally.
Referrer-Policystrict-origin-when-cross-originRequiredPrevents leaking full URL paths to third-party origins.
Permissions-PolicyDeny unused features: camera=(), microphone=(), geolocation=()RequiredReplaces the deprecated Feature-Policy header. Deny all features you don't use — empty () means "deny to all origins including self."
Cross-Origin-Opener-Policysame-originRecommended 2026Isolates your browsing context; required to enable SharedArrayBuffer & high-resolution timers safely. Defends against Spectre-class attacks.
Cross-Origin-Embedder-Policyrequire-corpRecommended for apps using SharedArrayBufferUse alongside COOP. Required for cross-origin isolation.
Cross-Origin-Resource-Policysame-origin (or same-site)Recommended 2026Prevents other origins from reading your resources via no-cors requests.
X-XSS-Protection0 (explicitly disabled)Deprecated — set to 0The legacy XSS Auditor is removed from all modern browsers. Setting non-zero values introduces client-side vulnerabilities. Disable it and rely on CSP.
Public-Key-Pins (HPKP)Do not useRemoved — do not implementDeprecated in 2017, removed from browsers in 2018. Complex to use correctly; misconfiguration causes permanent DoS. Superseded by Certificate Transparency.
Expect-CTDo not useObsolete as of 2021Certificate Transparency enforcement is now mandatory in all major browsers natively. Header no longer needed.
Cloudflare advantage: set these headers once in a CF Transform Rule and every one of your 300 apps inherits them immediately — no redeploy needed. On AWS, use CloudFront Response Headers Policies; on GCP, set them in Cloud Run service configuration or at the LB level.

9 Minimum security to ship — client checklist

The baseline every variant should satisfy before facing a client's security review. Pricing of these add-ons is detailed in the cost docs.

🔒 Common to every variant

  • TLS everywhere (HTTPS only, HSTS max-age=63072000; includeSubDomains; preload) — free on all variants
  • WAF + DDoS in front of all 300 apps (CF free / WAF + Shield / Cloud Armor)
  • Origin-lock so the edge can't be bypassed (secret header / internal ingress)
  • Per-route rate limiting at the front door
  • Security headers set at edge: CSP (nonce-based), X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, COOP/COEP; disable X-XSS-Protection (0); never implement HPKP
  • Secrets in a manager, never in code/images; rotate on a schedule; never commit to source control
  • SBOM generated per container image (SPDX or CycloneDX format); stored alongside the artefact
  • SLSA Level 2+ provenance from CI (GitHub Actions SLSA generator / Cloud Build / CodeBuild)
  • Centralised logging + 30–90 day retention; alerting on errors & auth failures
  • Audit log of admin / API actions, retained for review
  • Image / dependency scanning in CI (Trivy / Dependabot / ECR / Artifact Analysis)
  • Automated DB backups + a tested restore (RPO/RTO documented)
  • Least-privilege access to consoles; MFA on all admin accounts
  • AI scraper / LLM bot blocking if you serve content you don't want harvested for model training

11 Security verdict

Recommended: Variant ④ (GCP + Cloudflare)

Strongest edge security (free, CF) — including AI scraper blocking, Prompt Protection and MCP Server Portals — and deep network + data control with compliance (Cloud Run + Model Armor). Best balance of protection, low misconfig risk, and cost for this 300-app fleet — provided you lock the origin.

Lowest budget, low risk: PaaS stack ②

If the data is standard SaaS (no HIPAA/PCI/FedRAMP), the CF Worker front door delivers a client-ready security posture with the smallest surface to get wrong and almost no incremental security cost. AI Scraper blocking and AI Prompt Protection are included.

Strictest / regulated: AWS

When you need the deepest VPC isolation, BYOK, and the broadest compliance — and you have a platform/security team to own the large surface, WAF/Shield/GuardDuty spend, and the new Shield Network Security Posture Management.

Single-cloud compliance: GCP

Serverless economics with hyperscaler governance, compliance + BAA, one IAM/audit plane, and the new Cloud Armor hierarchical policies — plus Model Armor for AI workloads and Agentic AI SCC for threat detection — when single-vendor procurement matters more than the free CF edge.

13 Azure security features — serverless single-domain deployment (June 2026)

Reference security stack for Azure Container Apps (serverless, single-domain). Pricing is June 2026 list-price. Use this if evaluating Azure as an alternative to the four primary variants.

Azure WAF (Web Application Firewall)

Azure Front Door WAF · Application Gateway WAF
  • Azure Front Door WAF: OWASP Core Rule Set 3.2 (default-on managed ruleset); custom rules (IP, geo, rate, request-size); bot protection rule set included
  • Managed rule groups: OWASP Core (SQLi, XSS, RCE, LFI, RFI, Scanner, Protocol), Bot Manager, IP Reputation — all updated by Microsoft
  • Custom rules: up to 100 custom rules per policy; priority-ordered; match + rate-limit conditions
  • Pricing: $5/policy/mo + $1/rule/mo + $0.0000015/request for WAF processing; managed rule groups included in the policy fee
  • Modes: Detection (log only) and Prevention (block); use Detection first for baseline, then switch to Prevention
  • Must do: enable Prevention mode; tune OWASP exclusions to reduce false positives; configure geo-filtering rules; enable bot protection rule set

Azure DDoS Protection

Front Door Standard · DDoS IP Protection · DDoS Network Protection
  • Front Door Standard: Layer 3/4 DDoS mitigation INCLUDED at no extra cost — recommended for serverless single-domain deployments
  • DDoS Network Protection: $2,944/mo — enterprise-grade, VNet-scoped; overkill for pure serverless (Container Apps without VNet injection)
  • DDoS IP Protection: $199/public IP/mo — per-resource protection; cost-effective for 1–5 public IPs without full Network Protection
  • Always-on traffic monitoring: Azure DDoS basic (platform-level) absorbs volumetric attacks for free on all Azure resources
  • Recommendation for serverless: use Front Door Standard (L3/L4 DDoS free) + WAF ($5/policy) — full edge protection at minimal cost; skip DDoS Network Protection unless you have VNet-injected workloads
  • Must do: deploy Container Apps behind Front Door; never expose container app URLs (*.azurecontainerapps.io) directly — use ingress restrictions or private endpoints

Azure Key Vault

Secrets · Keys · Certificates
  • Secret storage: $0.03 per 10,000 operations; versioned, IAM-scoped, audit-logged; compatible with Container Apps managed identity (zero credential management)
  • Key operations (software keys): $0.03 per 10,000 operations; RSA/EC keys for envelope encryption
  • Key operations (HSM-backed keys): $1.00 per 10,000 operations; FIPS 140-2 Level 3; required for PCI-DSS / HIPAA BYOK
  • Certificate management: $3.00 per renewed certificate; automated renewal via DigiCert / GlobalSign integration; Let's Encrypt integration via ACME
  • Soft-delete: 90-day retention (configurable); purge protection available (prevents immediate deletion, even by admins)
  • Managed identity integration: Container Apps can pull secrets at runtime via system-assigned or user-assigned identity — no credentials in code or environment variables
  • Must do: enable purge protection; set RBAC (not legacy Access Policies) for Key Vault; restrict network access to VNet/private endpoint; audit Key Vault diagnostic logs

Azure Container Apps Security

Managed identity · VNet · Dapr · KEDA
  • Managed identity: FREE — system-assigned or user-assigned; no credentials to manage, rotate, or store; grants access to Key Vault, Storage, Service Bus, ACR etc.
  • VNet integration: available on dedicated workload profiles; supports internal-only ingress (no public endpoint); enables private connectivity to databases and internal services
  • Dapr sidecar: mTLS between services in the same environment by default; service-to-service auth via Dapr app tokens; secrets API backed by Key Vault
  • KEDA-based autoscaling: HTTP triggers (scale to zero when idle — zero attack surface when no traffic); event-based triggers (Service Bus, Event Hub, Azure Queue)
  • Container registry: pull from Azure Container Registry using managed identity — no registry credentials stored anywhere
  • Image scanning: Microsoft Defender for Containers scans ACR images for CVEs (usage-based pricing); integrate with SBOM generation in CI
  • Must do: set ingress to internal-only if behind Front Door; use managed identity exclusively (never connection strings in env vars); enable Defender for Containers; restrict egress via UDR if handling sensitive data

Azure Active Directory / Entra ID

OIDC · OAuth 2.0 · Conditional Access
  • OIDC / OAuth 2.0 built-in: Container Apps Easy Auth provides zero-code OIDC integration — supports Entra ID, GitHub, Google, Twitter; JWTs validated at the platform before the app sees the request
  • Conditional access policies: MFA enforcement, device compliance checks, named-location restrictions, sign-in risk policies — enforced at the identity plane, not the app layer
  • Free tier: unlimited users for core identity features (SSO, MFA with Microsoft Authenticator, basic conditional access); no per-user cost for standard SaaS scenarios
  • Workload identity federation: GitHub Actions, external OIDC providers can authenticate as managed identities without secrets — eliminates CI/CD credential sprawl
  • Entra ID P1/P2: advanced conditional access, PIM (Privileged Identity Management), Identity Protection — $6/user/mo (P1) or $9/user/mo (P2); required for regulated workloads
  • Must do: enable MFA for all admin accounts; configure conditional access; use PIM for privileged roles; enable sign-in logs + audit logs (route to Log Analytics)

Azure Compliance & Governance

SOC · ISO · HIPAA · FedRAMP · GDPR
  • SOC 1 / SOC 2 / SOC 3: Type II reports available; annual third-party audit; applies to Azure platform services including Container Apps, Front Door, Key Vault
  • ISO 27001 / ISO 27018: certified; ISO 27018 specifically covers protection of PII in cloud services
  • HIPAA / HITECH: Microsoft signs a BAA (Business Associate Agreement); Azure Container Apps, Key Vault, and Front Door are in scope
  • FedRAMP High: Azure Government regions carry FedRAMP High authorization; commercial regions carry FedRAMP Moderate for many services
  • GDPR: Azure is a Data Processor under GDPR; DPA (Data Processing Agreement) available; EU data residency via EU-only regions; Azure Policy enforces regional constraints
  • PCI-DSS Level 1: Azure platform is PCI-DSS Level 1 certified; Container Apps + Key Vault + Front Door are in scope; you are still responsible for your application's card data handling
  • Microsoft Defender for Cloud: continuous compliance score against NIST, CIS, PCI, HIPAA benchmarks; free foundational posture; Defender plans for enhanced protection (usage-based)
  • Must do: review Azure compliance documentation for your specific services; sign DPA/BAA before handling regulated data; enable Defender for Cloud foundational CSPM (free); assign Azure Policy for guardrails

Azure vs the four primary variants: Azure Container Apps serverless + Front Door WAF delivers a security posture comparable to GCP Cloud Run + Cloud Armor — L3/L4 DDoS free at the edge, managed OWASP WAF, managed identity for zero-credential secret access, and full HIPAA/PCI/FedRAMP compliance. The main gaps vs Cloudflare-fronted stacks are: no native AI scraper toggle (must write custom WAF rules), no equivalent to CF AI Prompt Protection (must use Azure OpenAI content filtering instead), and bot management requires Azure WAF bot protection (less sophisticated than Cloudflare Bot Management). For a team already on the Microsoft ecosystem, Azure is a strong fifth option.
Serverless origin-lock on Azure: when using Front Door + Container Apps, set Container Apps ingress to Limited to VNet (with VNet injection) or use the allowedIPAddresses ingress restriction to the Front Door service tag — otherwise attackers can hit *.azurecontainerapps.io directly and bypass the WAF entirely. Same pattern as the X-Origin-Secret approach in the Cloudflare variants.
